An L2 that Ethereum checks with its own proof program

A native rollup reuses the program Ethereum will use to prove its own blocks. Its L1 contract accepts an L2 block only with a proof of that program, so the L2 follows Ethereum's rules exactly, with no custom proof system of its own. This page runs one live on a local copy of frames-devnet-0, the devnet for EIP-8141 frame transactions.

    Moving ETH between L1 and L2

    Alice deposits from L1 and later withdraws. All L2 ETH comes from deposits: the L2 starts with no ETH outside a pre-minted supply that only deposits release, so L1 backs every L2 ETH.

    What we learned building it

    Problems and optimizations the demo surfaced, each now part of the design.

    One block could halt the chain

    Ethereum's rules accept a block at the maximum timestamp, after which no block can follow. The contract now keeps L2 time behind L1 time.

    Nobody could pay for the first transaction

    With no ETH on L2, no one could claim the first deposit. With frame transactions, a deposit pays for its own claim.

    The L2 and its contract need each other

    The L2's genesis names the L1 contract, which stores the genesis hash. The genesis is built for the address the contract will have.

    Half of each block's cost was new storage

    Keeping every L2 state root created a slot per block. Keeping the last 8,191 halves the cost of each block.

    Deposits cost a slot and a 3 KB proof each

    A Merkle tree of messages halves the L1 cost, and claims in the same block share one proof, leaving about 450 bytes each.

    Nodes could not find the data

    Without events, a node would scan every L1 transaction to find messages and blocks. The contract now announces both.

    Each block takes a whole blob

    Block-in-Blobs gives every block its own blobs. Blocks of a few KB fill 3 to 4% of theirs, while rollups today share blobs across many blocks.

    The program does not handle blobs yet

    Ethereum's validation program does not implement Block-in-Blobs yet. The design depends on it, and the demo checks the blobs in the node instead.
